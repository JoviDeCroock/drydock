# Detection rule behavior

What each deterministic rule family fires on, what it deliberately leaves quiet, and the fixture that pins each row. **Authority:** deterministic findings (AI review cannot downgrade them). **Owner:** `server/lib/review/rules/index.ts`.

Rule ids, severities, and fixture format: [`security-detection-corpus.md`](./security-detection-corpus.md). Why a rule changed: [`detection-rule-history.md`](./detection-rule-history.md).

## Archive reader behavior

`server/lib/tar-parser.js` records node-tar's path even where other extractors disagree. Disclosed parser differentials yield high `tar.suspicious-entry`; rule ID and severity stay the same for zip disclosures (`server/lib/review/rules/tar-entries.ts`).

| Shape | Consumer disagreement / recording contract | Pinned by |
| --- | --- | --- |
| Pure `.` zip segments | Collapse like tar: `./evil.pth` becomes `evil.pth`, its content inspected by `pypi.pth-execution`. | `test/zip-parser.test.mjs`, `test/pypi.test.mjs` |
| Leading `.` before `*.dist-info` / `*.data` | Remains unrepresentable: pip reads those directory names as written; collapsing would merge a metadata decoy with pip's real metadata. `..`, drive letters, backslashes and NUL remain unrepresentable too. | `cases-pypi/19-wheel-unrepresentable-zip-entry`, `test/zip-parser.test.mjs` |
| Zip disclosure | Carries `archive: "zip"`; explanation names pip for wheels and general zip extractors for VSIX, rather than node-tar / npm install. Content stays uninspected for rejected names. | `test/review.test.mjs` |
| GNU + pax path/link | GNU `L`/`N` plus pax `path`, or GNU `K` plus pax `linkpath`, on one member: node-tar merges metadata, last wins; CPython `tarfile` favors the first; family-strict readers keep GNU and pax separate or refuse (including uv tar-codec). | `test/tar-parser.test.mjs` |
| Repeated metadata | More than one long-name, long-link, pax `path` / `linkpath` / `size` record for a member; duplicate keys within one header count too (tar-rs keeps the first). | `cases-pypi/20-sdist-repeated-gnu-long-name` |
| Empty pax fields | Present-but-empty `path`, `linkpath`, `size` (`key=` or bare `key`) become empty under node-tar; POSIX treats them as deletion, exposing a prior/header value. | `test/tar-parser.test.mjs` |
| Global fields | Global `path` / `linkpath` ignored by node-tar, global `size` applied to subsequent entries; other extractors differ. | `test/tar-parser.test.mjs` |
| Oversized metadata | Local/global header over node-tar's 1 MiB limit is skipped by node-tar and applied by CPython; disclosed, not counted as a repeat. | `cases-pypi/21-sdist-oversized-pax-header` |
| Old GNU `N` | node-tar takes its long path; CPython has no `N` type and extracts the record as a separate file, keeping the member's header name. | `cases-pypi/22-sdist-old-gnu-name-record` |
| Empty `L` / `K` | node-tar ignores a zero-length record; CPython applies the empty name/link target. | `test/tar-parser.test.mjs` |
| Pax body | Newline splitting (node-tar) vs declared-length walking (CPython): untiled/unparseable lengths, missing `key=` (newer CPython refuses), differing `path` / `linkpath` / `size`, invalid UTF-8 path/link bytes (replacement characters vs raw bytes, even at equal length). | `cases-pypi/23-sdist-pax-body-length-mismatch` |
| Other pax keys | Not compared: macOS bsdtar's raw binary xattr values are harmlessly dropped by the UTF-8 line split. Body checks stay linear within the 1 MiB body cap. | `test/tar-parser.test.mjs` |
| Any `GNU.sparse.*` | CPython reconstructs bytes/size/name while node-tar installs raw body: 0.0 `numblocks` / `offset` / `numbytes`, 0.1 `map`, 1.0 `major` / `minor` with in-data map, plus `name` / `size` / `realsize`. A 0.1 map can reorder `system('x')import os;os.` into `import os;os.system('x')`. | `cases-pypi/24-sdist-gnu-sparse-map-reorder` |
| Pending pax `size` + metadata | node-tar before 7.5.22 (npm 11) also sizes the following metadata header's body with the pending value; node-tar 7.5.22 (npm 12) and CPython apply it only to the member. Records stay on npm 11's reading. | `test/tar-parser.test.mjs` |
| Magic-less ustar prefix | A header without the ustar magic but with a non-empty prefix field: node-tar ignores the prefix; CPython `tarfile` joins it unless an extended header names the member. Disclosed with CPython's path. | `cases-pypi/25-sdist-magicless-ustar-prefix` |
| Zip name encoding | Raw names decode as cp437 unless general-purpose bit 11 is set, as pip's `zipfile` and yauzl do; each record by its own flag, so a local/central disagreement fails closed. A version-1 Unicode Path field (0x7075) whose CRC matches the raw name renames the entry for CPython 3.12+ and yauzl but not CPython 3.11, so no single name is authoritative: one that normalizes to a different path, or is invalid UTF-8, fails the parse. A field that agrees is accepted; the Unicode Comment field (0x6375) is ignored, as every reader ignores it. | `cases-pypi/26-wheel-cp437-name-collision`, `27-benign-wheel-unicode-path-field`, `test/zip-parser.test.mjs` |
| PyPI duplicate | A duplicate whose replaced body differed (sha256) is high under the PyPI dialect, because pip may name the members apart or never reach the later one: CPython `tarfile` ends the archive at a mid-archive header it cannot decode (a non-octal mode such as `0000648`) that node-tar accepts, so pip installs the earlier body. Identical bodies (pyarrow ships some) and npm duplicates stay medium. | `test/review.test.mjs`, `test/tar-parser.test.mjs` |
| Directory by name | node-tar reads a `0`/NUL member whose final (pax or GNU) name ends in `/` as a directory; CPython `tarfile` only a NUL member whose own header name field ends in `/`, and consumes a body otherwise. Where they disagree, parses pip may read (PyPI `keep`, gate `package-prefix`) disclose it at size 0 and fail closed when a body is declared; npm's `strip1` parse is unchanged. | `cases-pypi/28-sdist-regular-typeflag-directory-name`, `test/tar-parser.test.mjs` |
| Rejected header (PyPI, gate) | node-tar skips a header it rejects without its body; CPython consumes the body or ends the archive. Parses pip may read fail closed on any; npm's parse keeps skipping and disclosing. | `test/tar-parser.test.mjs` |
| Link, device or FIFO body; old GNU sparse `S` | node-tar consumes a declared body; CPython reads none, and reads an `S` record's extension blocks as its sparse map, so the readers desync on every later member. Under parses pip may read, a body fails closed and any `S` record fails closed. | `test/tar-parser.test.mjs` |
| Zip end record | CPython and yauzl take the last end-record signature, place the directory by its declared offset and size, and switch to zip64 when a locator signature sits in the 20 bytes before. Wheels fail closed unless the end record names exactly the directory the stream walked, with no second signature in its comment and no locator. VSIX and GitHub artifact zips fail closed unless the comment reaches the file end, the directory ends at the end record, its records fill it exactly, and no locator precedes it. | `test/zip-parser.test.mjs` |
| VSIX `extension` prefix | VS Code strips a leading `extension` with no slash, so a root `extensionfoo.js` installs as `foo.js`. Records are mapped the same way, and one that lands on another entry's path fails closed. | `test/vscode.test.mjs` |
| Disclosure aggregation | One entry per member joins every local shape; unconsumed metadata disclosed at `<archive>`; global shapes once per archive. Attribution always keeps node-tar's recorded path. | `test/tar-parser.test.mjs` |

`test/tar-parser.test.mjs` rebuilds the sdists for cases 20–24 and asserts the fixture's exact file records and disclosures. Ordinary publisher toolchains emit at most one record of each metadata kind per member; sweep evidence is recorded in [`detection-rule-history.md`](./detection-rule-history.md).
