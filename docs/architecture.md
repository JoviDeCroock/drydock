# Architecture

Drydock reviews release artifacts before a maintainer approves publication. The authenticated scan pipeline handles npm registry-staged tarballs and GitHub workflow-gated artifacts through package adapters; the anonymous public-diff pipeline reviews atpm's public published and staged records without persisting them.

## Runtime components

```text
Browser UI
  │ same-origin authenticated fetch
  ▼
Hono Worker
  ├─ Better Auth session guard + organization ownership checks
  ├─ D1 persistence and R2 report/artifact storage
  ├─ Queue-backed scan/gate orchestration
  ├─ Dynamic Worker loader for untrusted archive parsing
  ├─ npm / PyPI / VS Code / atpm adapters, plus npm / PyPI / VS Code workflow gates
  └─ constrained brokers/gateways for registry/artifact downloads
        │
        ▼
      npm registry, PyPI, VS Code Marketplace, GitHub Actions artifacts,
      AT Protocol identity + PDS hosts (atpm)

Dynamic Worker sandbox
  ├─ receives scan options and artifact URLs, not npm credentials
  ├─ fetches only through `globalOutbound` brokers/gateways
  ├─ parses tarballs, wheels, and VSIX artifacts safely
  └─ returns bounded file metadata, text evidence, and suspicious-entry flags
```

The Worker is the trusted control plane; the sandbox treats package bytes as hostile evidence. Route handlers should stay thin and call shared pipeline/library code so HTTP routes, queue consumers, and local `waitUntil()` execution behave the same.

## Module layout

`server/lib/` is grouped by concern rather than by filename prefix. New files join an existing group instead of adding a prefix family at the root:

| Directory         | Holds                                                                                                                                                 |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `review/`         | Deterministic rules (`rules/`), package and manifest diffing, redaction, serialization, risk. `index.ts` is the entry.                                |
| `ai-review/`      | Versioned Workers AI advisory reviewer: prompt contract, evidence assembly, response types, traces, and eval contract.                                |
| `scan/`           | Scan lifecycle: pipeline and phases, queue job, input parsing, artifact persistence, report export, release memory.                                   |
| `public-diff/`    | Anonymous `/diff` orchestration, the `PublicDiffAdapter` contract, cache and error helpers.                                                           |
| `ecosystems/`     | One directory per ecosystem plus the registry that declares what each supports. See below.                                                            |
| `workflow-gates/` | Shared GitHub Environment gate plumbing (prepare, resolve, contract) — no ecosystem code.                                                             |
| `github-app/`     | GitHub App auth, webhooks, artifact retrieval, persistence.                                                                                           |
| `auth/`           | Better Auth wiring, ownership, roles, active organization, invitation tokens, audit-event allowlist.                                                  |
| `notify/`         | Outbound messaging: notification fan-out, Slack, email.                                                                                               |
| `platform/`       | Domain-free infrastructure: HTTP helpers, errors, fetch retry, JSON canonicalization, text/crypto utils, secret box, security headers, observability. |

Files that sit at `server/lib/` root are the ones no single group owns: the sandbox boundary (`sandbox.ts`, `tar-parser.js`) and the retention budgets that configure it (`sample-retention.ts`, read by both ecosystem adapters and `scan/`), the cross-cutting `compare-cache.ts`, and `workflow-gate-job.ts`.

## Ecosystems and capabilities

`server/lib/ecosystems/index.ts` is the single registry of ecosystems. Each one is a directory (`ecosystems/npm/`, `ecosystems/pypi/`, `ecosystems/vscode/`, `ecosystems/atpm/`) holding everything that ecosystem needs — acquisition, broker, findings, manifest parsing, and whichever capability adapters it implements — and the registry declares which of the three release paths it supports:

| Capability     | Field        | Contract                                | Meaning                                                                     |
| -------------- | ------------ | --------------------------------------- | --------------------------------------------------------------------------- |
| Registry stage | `staged`     | `PackageAdapter` (`package-adapter.ts`) | The registry holds a private candidate Drydock reviews before approval.     |
| Workflow gate  | `gate`       | `WorkflowGateAdapter`                   | A GitHub Actions publish job is held while Drydock reviews built artifacts. |
| Public diff    | `publicDiff` | `PublicDiffAdapter`                     | Two published versions diff anonymously on `/diff`, credential-free.        |

Today: npm has all three, PyPI has gate + public diff (the registry cannot stage a candidate), VS Code is gate-only, and atpm is public-diff-only (releases live in the publisher's own AT Protocol repository, which Drydock reads but neither stages nor gates — see [`atpm-public-diff.md`](./atpm-public-diff.md)). Capability presence is data, not convention — `getStagedAdapter` / `getWorkflowGateAdapter` fail closed with `UnsupportedEcosystemError` rather than falling back to another ecosystem's reviewer, and `test/workers/ecosystem-registry.test.ts` pins the matrix so a change to it is deliberate.

Adding an ecosystem means writing one directory and one registry entry. Routes and orchestrators read capabilities off the registry instead of branching on the ecosystem name, so a new ecosystem does not need to be threaded through `routes/public-diff.ts`, the gate router, or the scan job.

When an ecosystem needs behavior the shared runner does not have, add an optional method to the relevant adapter contract rather than an `if (ecosystem === …)` in the runner. `WorkflowGateAdapter.narrowParsedArtifact` is the worked example: PyPI collapses duplicate text samples across the dozens of platform wheels one release ships, and the shared gate runner just calls the hook when the adapter defines it.

The ecosystem id set is spelled once, in `ecosystems/labels.ts` (`EcosystemId`, `ECOSYSTEM_LABELS`, `isEcosystemId`). That module is dependency-free on purpose: the registry imports adapters, brokers, and the sandbox client, so the browser bundle reads labels from here instead, and persisted-value validators (`ReleaseProvenance.ecosystem`, report export) narrow through `isEcosystemId` rather than repeating the union.

## Trust boundaries

- **Browser/UI** — not trusted for authorization. It sends authenticated requests and renders escaped package text. It must not render package-provided HTML, scripts, images, SVG, or other active content.
- **Parent Worker** — authenticates users, resolves the organization, checks ownership, decrypts credentials only at the moment of registry use, invokes the sandbox, computes findings/risk, persists reports, and emits redacted audit events.
- **Dynamic Worker sandbox** — parses untrusted archive bytes. It must not execute code, install dependencies, resolve imports, run build steps, or receive token material.
- **NpmStageGateway** — the only place npm authorization is attached. Allowed npm egress is staged tarball fetch, package metadata JSON, and previous-version `.tgz` downloads needed for diffing. It also resolves redirects for pinned public artifacts (`publicArtifactUrls`) rather than letting the runtime follow them: same-origin hops only, bounded at three, so a pinned URL cannot be redirected to a host no policy admitted.
- **PyPiBroker / VscodeBroker / GitHub artifact broker** — credential-free PyPI artifact downloads are restricted to `https://files.pythonhosted.org`; VSIX baseline downloads are restricted to allowed Marketplace/CDN hosts; GitHub artifact access is scoped to the workflow-gate installation/run being reviewed.
- **atpm identity resolution** — the only egress whose host is chosen by the party under review: a DID document names its own PDS. It is credential-free throughout, and every URL is rebuilt from validated parts and re-checked against a public-host policy (https, no credentials, default port, no address literals, no loopback, protocol-reserved, local-use, or single-label names) before the parent Worker fetches it. PDS service endpoints must be bare origins rather than path prefixes. Automatic redirects are disabled; each parent-Worker hop is bounded and re-validated. Tarball bytes go to the sandbox with the blob URL pinned as the single allowed egress, and pinned artifacts may not be redirected off that origin. See [`atpm-public-diff.md`](./atpm-public-diff.md).

## Sandbox parser

Archive parsing is shared by the sandbox and tests rather than copied as strings. Tar parsing lives in `server/lib/tar-parser.js`; ZIP wheel/VSIX parsing is covered by `test/zip-parser.test.mjs` and adapter tests; shared fixture writers live in `test/helpers/archive-fixtures.mjs`. The parser enforces path safety, file-count and expansion caps, unsupported-entry reporting, duplicate-path handling, and fail-closed behavior. Both formats are parsed as a stream: entry bodies beyond the retention budget (`SANDBOX_MAX_TAR_BYTES`) — typically prepackaged platform binaries — are skipped rather than buffered, hashed with `crypto.DigestStream` on the way past, and recorded as `content-skipped` files/findings with path, size, and sha256 (so the diff can still prove whether an uninspected binary changed against the baseline); the first 64 discarded bytes are also retained and magic-byte sniffed (`sniffNativeArtifact`) into `native-elf`/`native-macho`/`native-pe`/`native-wasm` flags so extensionless platform binaries still raise `file.native-artifact`, all under a total stream cap (`SANDBOX_MAX_STREAM_TAR_BYTES`) enforced on both compressed wire bytes and decompressed output, so neither a high-ratio bomb nor padding that decodes to almost nothing can exceed the work budget. File counts are tiered the same way: `SANDBOX_MAX_FILES` bounds the full-inspection tier (bodies retained with text samples for detection), `SANDBOX_MAX_ENTRIES` is the hard cap on entries walked at all, and files past the tier are recorded hash-only like budget-skipped bodies — so big-but-honest sdists (numpy vendors its whole build system, 8k+ files) parse instead of failing. Bulk demotions (budget spent or tier filled) aggregate into a single `retention-tier` suspicious entry per cause rather than one entry per file; per-file `content-skipped` entries stay reserved for bodies over the per-file inspection limit. The streaming zip reader walks local file headers but cross-checks every central-directory record against them (consumers extract what the central directory says), failing closed on any mismatch and on data-descriptor, encrypted, or zip64 entries. VSIX archives are yazl-packed with data-descriptor entries, so they take a buffered central-directory-first parse under the wire cap instead of the streaming reader. `pnpm run fuzz` scales the archive-parser property suite for deeper exploration.

The sandbox also digests each archive's raw wire bytes as they stream past (`digestArchiveStream`). SHA-1 is the default because npm publishes it as `shasum`; adapters opt into additional algorithms only when their release contract needs them. atpm requests SHA-256 for its content-addressed blob CID and SHA-512 for npm-compatible SRI. The sandbox returns the selected results as `DownloadResult.archiveSha1` / `archiveSha256` / `archiveSha512`. This binds a review to the artifact it reviewed: the npm staged-publish adapter compares SHA-1 against the digest npm recorded for the stage (`evaluateStagedArtifactIntegrity`, in the ecosystem-free `lib/ecosystems/artifact-integrity.ts` so the report export and UI can re-validate the persisted verdict without reaching into an ecosystem directory), while atpm requires SHA-256 to match the release blob's CID and any declared SHA-512 `dist.integrity` to match the archive. A truncated or substituted download therefore cannot be reported as a publisher deleting files. The digester is deliberately not an inline tap that finalizes on flush — the tar reader stops at the end-of-archive marker and cancels, so the wrapper owns the source reader until its caller chooses the outcome: a successful parse calls `digest()` to drain the valid tar tail, while a parser/decompression failure calls `abort()` to cancel immediately instead of hashing hostile bytes for a discarded verdict. It reports digests only when it observed the source's own EOF, and null (never a partial digest) when the stream was cancelled upstream, errored, or ran past the digest cap. The digest cap is the _wire_ budget the parsers already read under (`SANDBOX_MAX_STREAM_TAR_BYTES`), not the decompressed-bytes cap: a tighter cap would switch verification off for exactly the large artifacts whose downloads are most likely to be truncated.

Retained bodies cross the sandbox→parent hop as one buffered JSON response, so how much text a parse retains is also how much parent memory it costs. The reviewed (staged/gated) side always retains **whole** bodies: deterministic rules scan `textSample` in the parent worker, and clipping the scanned text is the truncation hole that lets a payload hide past a fixed window (issue #191). The **baseline** side takes an opt-in per-file cap instead (`BASELINE_TEXT_SAMPLE_LIMIT` in `server/lib/sample-retention.ts`, 1 MiB — 8× the persisted display sample — plumbed as `maxTextSampleChars` → the sandbox's `MAX_TEXT_SAMPLE_CHARS` → `summarizeFile`), because a baseline body is never the release under review and is never persisted: it feeds line-level diff context, the recomputed baseline finding fingerprints, and AI diff context, each of which degrades toward _more_ release-delta findings when a baseline body is short (see [`diff-baseline.md`](./diff-baseline.md)). Manifest paths are exempt from the cap — manifest diffing is structural and a clipped manifest would null out package identity — and a clipped sample cuts on a line boundary and leaves `size`/`sha256` computed over every byte, so the diff can still prove whether the file changed. It is flagged `baseline-truncated`, deliberately not the `truncated` flag persistence puts on a reviewed file's display sample: `createPackageDiff` strips baseline retention flags rather than unioning them into `DiffEntry.flags`, so canonical report data (`summary_json.diff`, R2 `diff.json`, the exported `report.json`) never describes the reviewed release as clipped because the published side was. The flag stays on the baseline `FileRecord`, where the AI evidence builder reads it and notes that a capped baseline makes its tail render as additions. Binary/control-character classification also still reads the full body, so the `binary` flag means the same thing capped or not.

## Scan pipeline

`server/lib/scan/pipeline.ts` is the canonical orchestration layer. It accepts a `PackageAdapter` from `server/lib/ecosystems/package-adapter.ts`, then delegates ecosystem-specific behavior:

- input parsing and staged-detail summaries;
- artifact acquisition and baseline selection;
- package projection and deterministic findings;
- changed-file diff construction;
- report persistence and scan lifecycle updates.

`POST /api/v1/scans` creates a queued scan record. A Queue consumer in production, or local `waitUntil()` execution in development, runs the pipeline. `DELETE /api/v1/scans/:id` removes an organization-owned scan only when its persisted status is `failed`; all other lifecycle states return `409` and remain intact.

Peak memory is what caps reviewable package size — a scan holds both package sides in a 128 MiB isolate — so the pipeline is ordered so that nothing after deterministic findings can reach an unredacted body. `analyzeRelease` acquires both sides, diffs them, runs deterministic findings over **raw** text, projects what later phases need into `ArtifactFacts` (package summary, file counts, baseline, the intent envelope's declared repository), and releases the raw file arrays; `ResolvedArtifacts` never leaves that call, and `persistResults` takes the facts rather than the artifacts. `ComputedDiff.stagedManifestText` is raw manifest text the rules read, so it is dropped at the same boundary. Anything later phases want from the raw evidence has to become a fact here — reading it after the boundary does not fail loudly, it silently reads nothing. Findings must run _before_ redaction, and everything that crosses the boundary is redacted.

Be precise about what that release frees: redaction copies the _records_, not usually the text — a `String.replace` that matches nothing returns its receiver, so a clean file's raw and redacted records share one sample string. What is reclaimed is the record wrappers and both arrays, the raw text of files redaction actually rewrote, and — the durable part — the guarantee that AI review, risk scoring, report assembly, and persistence are never handed a raw body. The release is also a no-op for the workflow-gate path: those artifacts were parsed before the pipeline ran and stay referenced by the gate's prepared-package list (up to three packages scanned concurrently) for the whole gate run. It is effective for registry-staged scans, where the pipeline owns the only reference.

Registry packument reads on this path are cached for 5 minutes in `COMPARE_CACHE` (`fetchPackageMetadataCached`, shared with the compare/versions routes). Cache keys are organization-scoped (`org:<id>`), because a packument fetched with one organization's npm token may include private packages another must not see, and the scan path asks for npm's abbreviated packument (keyed separately, since only the full document carries per-version `time`). Every registry document is projected down to the fields Drydock reads (`versions[].dist.tarball`, `dist-tags`, `time`) at the fetch boundary, so a package with thousands of versions does not keep megabytes of readmes and per-version manifests resident for the length of a scan. Staleness is bounded but not free: normally it selects an older baseline than the freshest publish, which the report records in `BaselineInfo` and which makes the diff louder rather than quieter. A dist-tag that moves _backwards_ within the TTL (a rollback) is the exception — the cached tag still points at the withdrawn newer version, so that release is diffed against a baseline ahead of it and reads quieter than it should. Five minutes is the window; the baseline version in the report is how a reviewer sees which one was used.

The UI polls `GET /api/v1/scans/:id/status` — one indexed row read, projected to the lifecycle columns and excluding `summary_json`/`ai_json`/`error_json` — and fetches the full `GET /api/v1/scans/:id` detail once, on the transition to a terminal status.

Baseline selection is tag-aware rather than simply highest-semver; see [`diff-baseline.md`](./diff-baseline.md).

## Workflow gates

Workflow gates reuse the scan pipeline when the registry cannot stage a release candidate. GitHub Actions uploads built release artifacts, GitHub Environment deployment protection pauses the publish job, and Drydock reviews artifacts before posting an accept/reject decision back to GitHub. Shared gate plumbing lives under `server/lib/workflow-gates/`; ecosystem details live in adapters. Large compiled PyPI releases use the conventional `pypi-release-candidate-*` shard family: each outer Actions ZIP remains capped and is downloaded, digest-verified, sandbox-parsed, and discarded before the next shard, while compact parsed evidence and provenance for every wheel/sdist are retained. Matching public baselines are likewise sandboxed sequentially, and identical logical text samples repeated across platform wheels are retained only once; paths, hashes, sizes, and flags remain per artifact so a divergent platform wheel stays independently visible. The baseline mirrors the staged side's retention decision so both sides of a wheel namespace either both carry a body or neither does, and a changed file never renders as a one-sided hunk. Shard-family discovery is opt-in per ecosystem (`shardedArtifactNames`, PyPI only) because a prefix match widens discovery; npm and VS Code keep the exact-name match. The larger shard budget applies only to release targets that pin an ecosystem; auto-detect targets match every artifact on the run and keep the smaller single-upload budget. A distribution filename that arrives from more than one shard is accepted once when the bytes are identical and fails the gate when they are not, so the manifest and provenance never bind two digests to one path. When a published baseline exists but exceeds the download budget, `BaselineInfo.comparisonSkipped` records it: findings are annotated `unknown` package context rather than release deltas, the report leads with "no baseline to compare", and the gate's advisory recommendation is `manual_review` — an uncompared release is never graded as if it added every file it ships. See [`workflow-gates.md`](./workflow-gates.md).

## Scheduled discovery

Cron-triggered npm discovery finds staged publishes for organizations with validated npm connections and creates scans using the same pipeline. Token-expiry and validation issues should surface through settings/UI status and redacted observability events.

A per-org sweep failure is logged as `staged_publishes.cron.org_failed` with a `transient` field. Registry transport failures (status `0` — timeout, DNS, TLS) and 408/429/5xx responses are classified transient by `isTransientSweepFailure` and logged at **warn**: `reliableFetch` has already retried, discovery is idempotent, and the next 15-minute tick re-sweeps the org, so the cost is at most one cycle of detection latency. Everything else — unexpected statuses, D1 failures, bugs in the sweep — stays at **error**. Expired tokens never reach this log; they take the `recordExpiredNpmConnection` path instead. Repeated transient failures for one org are deliberately not escalated here; that would need failure counting across ticks.

Within a single org sweep, new staged publishes are started through a bounded-concurrency pool capped at `STAGED_PUBLISH_SCAN_START_CONCURRENCY` (`mapWithConcurrency` in `server/lib/ecosystems/npm/staged-publishes-discovery.ts`) rather than sequentially. Because the same staged publish can be visible to more than one organization, a cron invocation shares a `StageStartCoordinator` across its concurrent org sweeps: matching stage IDs are started one at a time, while each org still gets its own scan row and queue message. Raise the concurrency constant only after measuring CPU time per tick.

## Data stores

- **D1** — Better Auth tables, organizations, npm connections, scans, scan files/findings, workflow gates, release targets, summaries, and audit/event metadata. D1 remains the operational source of truth.
- **R2** — canonical report JSON and redacted file/diff artifacts. D1 keeps compact metadata and historical fallback samples so list/detail pages remain cheap.
- **KV** — session-related state where configured.
- **Workers AI / AI Gateway** — optional advisory review path. The per-organization `ai-review` Flagship flag is a killswitch that is on by default; deterministic findings remain authoritative. Sampled Agent Traces retain no message or tool payloads; Analytics Engine stores only aggregate execution and decision dimensions keyed by reviewer version.

## Organization and auth model

All non-auth `/api/*` endpoints require a Better Auth session and an active organization, with one deliberate exception: the anonymous public package-diff endpoints under `/api/public/v1/package-diff` (below). Users may belong to multiple organizations; scan data, npm connections, workflow gates, release targets, Slack installs, and settings must be organization-scoped. Email verification and membership/invitation behavior are described in [`organization-members.md`](./organization-members.md).

## Public package diff

`/diff` is an anonymous marketing/utility surface: it diffs any two published versions of an npm package, PyPI project, or atpm package and runs the deterministic rule set over the newer artifact, reusing the scan pipeline's pure phases (`server/lib/public-diff/index.ts`, with each ecosystem's acquisition in its own `public-diff.ts` under `server/lib/ecosystems/`, routes in `server/routes/public-diff.ts`). On npm, either side of the pair may also be a [pkg.pr.new](https://pkg.pr.new) continuous-release preview URL (validated by the shared parser in `src/lib/pkg-pr-new.ts`), so a pull-request preview build can be reviewed against a published release before it ships; preview refs are mutable, so pairs involving a preview are cached for at most 15 minutes and preview bytes never enter the shared tarball-byte cache. The endpoints take an `ecosystem` query parameter (`npm` default, or `pypi` / `atpm`); npm data comes from the canonical public npm registry, PyPI data from the `pypi.org` JSON API with artifact bytes only from `files.pythonhosted.org`, and atpm data from the publisher's own AT Protocol identity and PDS with no registry in the path at all — see [`atpm-public-diff.md`](./atpm-public-diff.md) for the resolution chain and the host policy that bounds it. Because a PyPI release can carry dozens of platform wheels, each side of a PyPI diff is bounded to one sdist plus one wheel — preferring a wheel shape both versions publish, then the pure-Python `py3-none-any` wheel — and artifact contents are namespaced (`sdist/…`, `wheel/<tags>/…`) in the diff tree. The selected artifacts across both versions also share a 50 MiB advertised-download budget. When both comparable artifact kinds do not fit, the cheaper wheel or sdist pair is reviewed and the omitted kind is disclosed in the response; comparable pairs are parsed one at a time so at most two sandbox Workers inflate archives concurrently. The endpoints are mounted before the auth middleware, use no credentials, and are enabled only when `NPM_REGISTRY` is the canonical public npm registry; deployments configured for a custom registry return 404 for this API (including its PyPI mode, since a custom registry signals a private deployment). They persist no review data to D1 and never run AI review. Abuse control is per-IP rate limiting (Cloudflare native Rate Limiting bindings, so the anonymous surface touches D1 on no request path; see [`security-model.md`](./security-model.md#rate-limiting)), the shared anonymous tarball-byte cache described in [`diff-baseline.md`](./diff-baseline.md), and a versioned computed-result cache: an awaited `caches.default` write makes the first file navigation immediately available in the serving colo, while a 30-day `COMPARE_CACHE` KV entry supports cross-colo reuse. File-content cache misses share the stricter version-pair computation budget, while cache hits retain a higher navigation allowance. Cache keys include the ecosystem and the deterministic-rules and risk-schema versions (PyPI keys additionally carry the PyPI rules version and normalize the project name per PEP 503) so detection changes cannot reuse stale assessments. A pair whose payload exceeds the cache value budget (measured in UTF-8 bytes) does not lose every file sample: retention is prioritized — changed paths first, then unchanged ones as package context under their own much smaller sub-budget, cheapest sample first inside each tier — and both sides of a path are always kept or dropped together so a modification never renders as a one-sided hunk. The unchanged sub-budget exists because every file navigation re-reads and re-parses the whole cached payload, so a reduced payload must not grow back to the full cache limit. Records that lost their sample carry a `sample-omitted` flag, which the diff view surfaces as a badge, an explanatory message, and the file's sha256 identity lines instead of implying the body was never inspected; only a pair whose changed files alone do not fit falls back to caching metadata with no samples at all. Payload sizes are computed by counting UTF-8/JSON bytes rather than encoding throwaway copies, because these strings are tens of MiB on exactly the releases that trip the budget and the Worker is still holding both parsed sides. Sandbox archive caps bound per-request work. Version-pair responses require origin revalidation so a deployment cannot leave browsers on an older analysis, while `Cache-Tag: public-diff:<package>` (npm) and `Cache-Tag: public-diff:pypi:<project>` remain available for package-level purges. An ecosystem may also return a resolution trail (`provenance`), rendered as label/value evidence whose links are rebuilt from validated resolution parts rather than from raw publisher-controlled values, and a `displayName` for when its canonical package name is a DID rather than the readable handle. Only atpm supplies either today: locating one of its releases is a chain of independent authorities rather than a single registry, and its canonical name prevents ordinary handle reassignment from redirecting a shared link, while the page, title, and share card render the verified `@handle/name`; `did:web` ownership remains domain-bound and is explicitly disclosed. The static `/diff` shell is also used for direct detail URLs (`/diff/<name>/<from>/<to>` for npm, `/diff/pypi/<project>/<from>/<to>` for PyPI, `/diff/atpm/<did>/<name>/<from>/<to>` for atpm, whose handle form redirects to the canonical DID URL), with Worker-side HTML rewriting of package-specific title, description, Open Graph, Twitter, and canonical metadata before the client renders. That rewrite includes a per-diff share card: `og:image`/`twitter:image` point at `/og/diff/<name>/<from>/<to>/card.png` (`/og/diff/pypi/<project>/…`, `/og/diff/atpm/<@handle-or-did>/<name>/…` for the prefixed ecosystems), served by `server/routes/og.ts`. The card path mirrors the page path through the shared `packageDiffCardPath` helper so a scoped name or preview ref can never be encoded two different ways, and it carries no query string because a raw `&` in an `og:image` attribute is an ambiguous ampersand that strict scrapers mis-parse. The SVG is composed in `server/lib/public-diff/card.ts` (pure, [`docs/design.md`](./design.md) light-mode tokens) and rasterized by `@resvg/resvg-wasm` in `server/lib/public-diff/card-render.ts`, which loads the two Geist TTFs from `public/fonts/` through the ASSETS binding once per isolate rather than bundling ~270KB of font into the Worker. Cards read the public-diff result cache for their file/finding counts and never trigger a cold computation; a cache miss renders the package and version pair without numbers. Renders are per-IP rate limited (charged only on a colo-cache miss), stored in `caches.default`, and tagged with the same purge tag as the JSON payload; a font or rasterizer failure falls back to the static site card with a 60-second TTL so a shared link never unfurls broken. Findings run on raw text samples before redaction — the same order as the scan pipeline — and only redacted evidence is cached or returned.

Each computed pair also carries an advisory **capability projection** (`server/lib/review/capabilities.ts`): per-side sets over `network` / `process` / `credentials` / `dynamicEval` / `native` / `installScripts` / `bin`, derived from the same pattern sets the deterministic rules match plus the manifest and the parser's file flags, with a cross-version `escalations` / `reductions` delta. The projection is honest about coverage — files whose bodies were never content-inspected are counted per side, and a delta over uninspected bytes is marked unconfident so an empty escalation list cannot read as "no escalation". Like the intent envelope, capabilities never feed risk or findings; the same delta is computed by the scan pipeline (persisted in `summaryJson.capabilities`, exported in `drydock.report.v2`, shown as a Capabilities row on the workbench and `/diff`, and handed to the AI reviewer as context).

`GET /api/public/v1/package-diff/verdict` projects a computed pair into `drydock.verdict.v1`, the machine-readable form the dependency-update integrations consume (`server/lib/public-diff/verdict.ts`, a pure projection of the cached payload — a verdict never costs more than the diff it summarizes). The payload carries identity, per-side publication timestamps, the analysis version (`rulesVersion`), a three-tier `grade` (`clear` / `notable` / `needs-review`, folded from artifact + release risk with `needs-review` as the ceiling), per-severity finding counts, the capability delta, declared-tier source binding with a `changed` flag, coverage accounting, and the `/diff` URL a human should read — and deliberately no finding text or rule ids; see [`security-model.md`](./security-model.md) for that posture. Rate limiting mirrors `/file`: a cached pair costs the verdict's own per-IP bucket, a cold pair additionally spends the shared expensive computation budget.

## npm connection model

Organizations store their own encrypted npm connection. The UI validates baseline registry auth/list access after save; discovery and scan workers re-check validation before use. Custom registries are supported, but token use still flows only through the constrained npm gateway.

## Report model

Reports remain canonical and signable: stable ordering, explicit release/artifact/context risk sections, redacted evidence, and enough metadata to reproduce the reviewed artifact identity. The canonical export (`drydock.report.v2`) is the signing boundary — publicly shared reports serve those exact bytes at `/public/reports/:token`, and the attestation endpoint signs their SHA-256 inside a DSSE envelope (see `public-reports.md`). `GET /public/reviews/:ecosystem/*?version=&digest=` is the machine bridge from an exact public package artifact to its capability-bearing public report page: it queries only `public_package_key` rows (populated while feed-listed), requires the caller's SHA-1 or SHA-256 to match verified reviewed-byte evidence, reports that digest with package-identity strength plus the normalized intent-envelope tier, and returns one uniform `{ listed: false }` result for every non-public or byte-mismatched state. Changing the export shape changes the attested bytes, so bump the schema tag when consumers must branch.

## API direction

Keep request/response types shared between `server/` and `src/`. Prefer route helpers and typed fetch wrappers over ad hoc shape duplication. New API behavior should update this file only when it changes runtime shape, trust boundaries, storage, or cross-layer contracts; otherwise point to route-local tests and code.
